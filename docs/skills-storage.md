# Хранение и подключение скиллов

Единственный источник — постоянный клон репозитория. Тематическое дерево восстановлено по `ce70de5c`; новые скиллы добавляются в соответствующую категорию.

```text
skills/
├── System/main-rule/
├── engineering/
│   ├── ai-docs-setup/           # контракт проектной памяти (AGENTS.md, .ai/)
│   ├── dandy-commit/
│   ├── grill-me/
│   ├── obsidian/
│   └── wayfinder/
├── in-dev/                      # Не устанавливается и не применяется по умолчанию
│   ├── code-improvement/
│   ├── obsidian-framework/
│   └── project-workshop/
├── code/
│   ├── api-integrations/
│   ├── dandy-style/
│   ├── laravel-strict/
│   ├── laraway/
│   ├── moonshine/
│   ├── pest-testing/
│   └── wordpress-clean-plugin/
├── seo/
│   ├── diagnostika-padeniya-trafika/
│   ├── geo-aeo-llm-poisk/
│   ├── seo-getting-started/
│   └── seo-audit-tehnicheskiy-kontentnyy/
├── tools/{find-skills,web-search}/
└── ui-ux/{dandy-design,frontend-skill,frontend-ui-ux-design}/
```

Каждый конечный каталог содержит `SKILL.md`, а при необходимости — `recipes/`, `references/`, скрипты. Категории не являются скиллами. Имена конечных каталогов уникальны; установщик ищет их рекурсивно, но не заходит в содержимое найденного скилла, скрытые каталоги и `in-dev`.

## Эксперименты: in-dev и OF

`skills/in-dev/` — незавершённые эксперименты. Не использовать их инструкции и рекомендации, не активировать и не подключать по умолчанию. Работа с ними — только по явному поручению.

OF (Obsidian Framework) — **экспериментальный проект и скилл** `skills/in-dev/obsidian-framework/`. Статус относится также к его CLI, шаблонам и генерируемым инструкциям. Прежние технические имена `bin/obsidian-project-framework` и `src/obsidian-project-framework/` пока сохранены. `code-improvement` и `project-workshop` также находятся в `in-dev`.

Установщик исключает эксперименты из справки и любых установок, в том числе по явно указанному имени. Автоматическая очистка ранее установленных копий и ссылок не выполняется: их нужно проверить отдельно, с резервной копией. CLI выбирает доступные скиллы по имени каталога.

## Постоянные ссылки для всех проектов

Из корня постоянного клона:

```bash
./bin/skills-install --global --link-source --dry-run
./bin/skills-install --global --link-source
# Или выборочно:
./bin/skills-install --global --link-source laraway pest-testing
```

Для каждого скилла создаётся прямая ссылка на его исходную папку в:

- `~/.agents/skills/` — общий каталог;
- `~/.claude/skills/` — Claude Code;
- `~/.config/opencode/skills/` — OpenCode;
- `~/.pi/skills/` — Pi;
- `~/.cursor/skills/` — Cursor с поддержкой Agent Skills.

Без `--global` используются проектные `.agents/skills`, `.claude/skills`, `.opencode/skills`, `.pi/skills`, `.cursor/skills`.

Целевые каталоги содержат **плоский список ссылок на скиллы**, не копию тематического дерева. Изменения исходников сразу видны агентам. После добавления скилла повторить команду; после перемещения клона ссылки нужно перенастроить. Не использовать `--link-source` из временного клона удалённого установщика.

`--dry-run` ничего не создаёт. Режим `--link-source` предварительно проверяет все целевые имена: существующие каталоги, чужие и битые ссылки не заменяются; при конфликте установка прекращается до записи. Сначала сделайте резервную копию конфликтующих каталогов и разберите их вручную. Уже существующие ссылки всего каталога допустимы, но запись через них меняет их фактическую цель.

Обычный режим без `--link-source` сохраняет прежнюю установку копиями; он не предназначен для ручного редактирования единственного источника и может заменять установленные версии.

## Zed

Не создавать выдуманный `~/.zed/skills` или `~/.config/zed/skills`. Для внешнего агента через ACP подключать скиллы в каталог этого агента (Claude Code, OpenCode и т. п.). Для встроенного агента проверять поддержку Agent Skills в установленной версии Zed отдельно; наличие общего каталога само по себе не гарантирует загрузку инструкций.

## Безопасность

Глобальные инструкции доступны во всех проектах — подключайте только доверенные скиллы, без секретов и проектных данных. Перед перестройкой домашних каталогов сохраняйте резервную копию. При перемещении исходников уже существующие ссылки на них нужно перенаправить с сохранением прежних целей в резервной копии; чужие скиллы не трогать.

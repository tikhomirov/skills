# Коллекция скиллов для агентов

Исходники хранятся по темам в этом репозитории. Каждый скилл — отдельный каталог с `SKILL.md`; агентам подключается плоский список симлинков на эти каталоги.

## Структура

- `skills/System/` — общие правила.
- `skills/code/` — PHP, Laravel, MoonShine, WordPress, API и тесты.
- `skills/engineering/` — инженерные инструменты, Obsidian, review.
- `skills/seo/` — SEO, диагностика и GEO/AEO. `seo-getting-started` — первый разговор с владельцем: сайты, цели, доступы и правила; аудит только после согласия.
- `skills/tools/` — поиск и обнаружение скиллов.
- `skills/ui-ux/` — дизайн и frontend.
- `skills/in-dev/` — эксперименты, исключённые из обнаружения и установки.

## Подключение постоянного клона

Нужны Git и Node.js 20+. Obsidian для установки коллекции не требуется.

```bash
git clone https://github.com/tikhomirov/skills.git
cd skills
npm ci
./bin/skills-install --global --link-source --dry-run
./bin/skills-install --global --link-source
```

Конфликтующие каталоги и чужие ссылки не заменяются. Сначала сохраните резервную копию и разберите конфликт вручную. После добавления скилла повторите команду; изменения существующих исходников сразу доступны через ссылки.

Каталоги агентов и ограничения Zed: [хранение и подключение](docs/skills-storage.md).

## OF — Obsidian Framework: в разработке

**OF — экспериментальный проект и скилл, не готовое решение и не обязательный процесс работы.** Статус относится ко всему проекту: инструкциям, CLI, шаблонам и генерируемым документам.

Эксперименты:

- `skills/in-dev/obsidian-framework/` — OF;
- `skills/in-dev/code-improvement/` — инструкции по улучшению кода;
- `skills/in-dev/project-workshop/` — диалог настройки проекта.

На них нельзя опираться при обычной работе. Не активировать и не подключать по умолчанию; разработка и тестирование — только по явному поручению. Установщик не показывает и не устанавливает `in-dev`, даже при явном указании имени скилла. Уже существующие внешние ссылки автоматически не удаляются.

Код OF пока сохраняет прежние технические имена: `bin/obsidian-project-framework`, `src/obsidian-project-framework/`, `tests/obsidian-project-framework/`. Наличие CLI и успешных тестов не означает готовность проекта. Справочный раздел OF в [README.md](README.md) описывает эксперимент, а не рекомендуемый сценарий установки.

## Проверки разработки

```bash
make check
make test
make help
```

Тесты используют временные каталоги, а не пользовательские проекты или Vault. Живые данные менять только по поручению и с резервной копией.

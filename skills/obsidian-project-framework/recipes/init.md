# Инициализация без создания модулей

```bash
obsidian-project-framework init --vault <vault-path> --project demo
obsidian-project-framework init --dry-run
# Доска Tasks/_Задачи.base создаётся автоматически (Obsidian 1.14+).
```

1. Прочитать AGENTS репозитория и правила Vault, определить id проекта. Не дублировать Projects/ и Проекты/.
2. Создать служебные каталоги, Tasks/ (или использовать существующую Задачи/), Решения/, `_agents/{Memory,Knowledge,Reports}` и отсутствующий AGENTS. Заполнить рабочую карту в `_agents/Knowledge/Карта проекта.md` только проверенными сведениями.
3. Не создавать Модули/ или API/ автоматически. Исследовать компоненты и спросить пользователя о составе, названиях и расположении модулей. Дождаться подтверждения.
4. При числе менее 10 предложить `01_Имя/`, `02_Имя/` в корне или `Модули/<Имя>/`. Это выбор пользователя, не жёсткая автосхема. API согласуется как обычный модуль.
5. Записать принятое решение отдельным событием. Подтверждение списка модулей само по себе не разрешает писать документацию — для создания/изменения документов нужна явная просьба.
6. Проверить doctor. Архитектуру не выдумывать; в существующие AGENTS/Архитектура.md без разрешения не писать.

Повтор init создаёт только недостающее и сохраняет пользовательские данные. `--force` обновляет шаблоны и запрошенное представление Bases, но не правила/память. В корне создаётся `_statuses.md` с описанием начальных статусов backlog / in-progress / done. Это источник истины; пользователь может менять и расширять список. Существующий реестр не перезаписывать даже с --force.
`_Задачи.base` создаётся и актуализируется по умолчанию: это **нативный Kanban**, а не таблица, с колонками в порядке из `_statuses.md` и фильтром по текущей папке задач. Требуется Obsidian 1.14+. Неизвестные старые статусы нужно явно согласовать: init не создаёт доску, которая молча скроет такие карточки. Dry-run не создаёт даже каталоги/lock.
Старые Agents/AGENT/HUMAN и корневые Memory/Knowledge/Отчеты не удаляются автоматически. Перенос — отдельное поручение; существующие проекты не перестраивать ради примера.

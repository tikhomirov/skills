# Решения пользователя: append-only история

```bash
obsidian-project-framework decision record "API — модуль приложения" \
  --key api-module --task TASK-001 --related TASK-002 \
  --summary "Пользователь подтвердил API в составе модулей" \
  --source "Ссылка на сообщение или точная цитата пользователя с датой"
```

Записывать только действительно принятые пользователем ключевые решения. Аргумент source — свидетельство согласования, а не возможность выдумать его. Сам скрипт не подтверждает авторство сообщения.

Событие содержит содержание, время записи, источник подтверждения с фактической датой решения, стабильные id задач и связи с предыдущими решениями. Если решение принято раньше, передать `--decided-at YYYY-MM-DD` с фактической датой; время записи сохраняется отдельно в recorded_at. Если флаг не указан, событие относится к моменту записи. Не выдумывать неизвестную дату. Новые записи создаются эксклюзивно: существующий файл нельзя заменить.

Если пользователь изменил решение:
```bash
obsidian-project-framework decision record "Новое расположение API" \
  --key api-layout-v2 --task TASK-003 --supersedes DEC-<id> \
  --summary "Новое решение пользователя" --source "Сообщение пользователя с датой"
```

Старое решение не редактировать, не переименовывать и не удалять. Исправления, отмены и уточнения — новые события. `supersedes` связывает события в граф, исходная запись остаётся прежней.

Для навигации генерируется `_agents/Knowledge/Решения — таймлайн.md`: хронология со ссылками на решения и текущие карточки задач. В неизменяемых событиях использовать `task_ids`, не изменяемые имена карточек. При смене статуса меняется таймлайн в рабочей зоне, но не Решения/.

Идемпотентность: одинаковая запись с тем же ключом возвращает прежний файл. Попытка заменить содержание при том же ключе завершается ошибкой; нужен новый ключ/событие. Dry-run ничего не пишет.

# Пользовательский реестр _statuses.md

В корне проектной базы создаётся `_statuses.md`: единственный источник допустимых статусов задач, их смысла и порядка колонок канбана. Init создаёт его для каждого проекта; если пользователь попросил изменить статусы в проекте без этого файла — сначала создать реестр.

## Начальная таблица

```markdown
| status | Название | Роль | Описание |
|---|---|---|---|
| backlog | Backlog | backlog | Задача запланирована. |
| in-progress | In Progress | active | Работа выполняется. |
| done | Done | done | Результат и проверки записаны. |
```

Это начальные значения, не жёсткое ограничение. Пользователь может добавлять, удалять, переименовывать и переставлять статусы. Агент делает это только по явной просьбе и сохраняет понятное описание каждого значения.

- status: уникальный идентификатор латиницей, строчными буквами, цифрами и дефисами. Используется в Properties, имени файла и статусном теге.
- Название/Описание: смысл статуса для пользователя и агентов. Нативный Kanban подписывает колонку самим значением status.
- Роль: backlog (не начато), active (работа/проверка/ожидание), done (готово, обязательны отчёт и проверки). Для каждой роли нужна хотя бы одна строка. Число статусов каждой роли не ограничено.
- Порядок строк: порядок колонок `_Задачи.base`.

Например, по просьбе пользователя перед done можно добавить:
```markdown
| review | Review | active | Ожидает проверки результата. |
```

## Правила агента
1. Прочитать реестр перед созданием/изменением задач. Не брать список из памяти, скилла или констант программы.
2. create выбирает первый backlog, start — первый active, complete — первый done. Для конкретного статуса использовать task status TASK-ID status.
3. Если реестр отсутствует/повреждён — сообщить и восстановить согласованную конфигурацию; не продолжать с молчаливым fallback.
4. После изменения выполнить `obsidian-project-framework task sync`, затем doctor: доска получает новый groupOrder, карточки сохраняют имена/теги/связи.
5. При переименовании/удалении сначала добавить новые строки, явно согласовать сопоставление существующих задач, перевести их через task status, затем удалить старые определения и выполнить sync. Не преобразовывать статусы по догадке.
6. Init не перезаписывает пользовательский реестр, даже с --force. Изменение исходного файла — явная пользовательская правка; доска и навигация генерируются по нему.

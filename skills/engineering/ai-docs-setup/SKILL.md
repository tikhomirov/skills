# Проектная память: контракт

Скилл — процедура «как делать» (глобальная). Память — факты «в этом проекте так».
Скилл с фактами проекта устаревает вместе с проектом; память с процедурой дублирует скилл.

## Раскладка

```text
AGENTS.md              # правила, карта кода, карта документации, порядок проверок
.ai/
  project-rules.md     # только если AGENTS перерос бюджет
  glossary.md
  index.md             # карта Knowledge/Reports: файл → одна строка
  Memory/              # NOW.md, STATE.md — только для длинных задач
  Knowledge/  Reports/
.agents/skills/        # процедуры проекта
```

`.project-id` допустим, если проект его уже использует. Процедурные скиллы не класть в Knowledge — ставить через `skills-install`.

## Бюджеты

| Файл | Лимит |
|------|--------|
| `AGENTS.md` | ~100–150 строк |
| `.ai/project-rules.md` | только дополнения к AGENTS, не копия |
| Memory-файлы | коротко; с датой и автором |

Превысили бюджет — агент не дочитывает. Длинные таблицы и примеры выносить в Knowledge и ссылать из `index.md`.

## Приоритет источников

1. Живая инструкция человека в текущем чате
2. `AGENTS.md` проекта (и `.ai/project-rules.md`, если указан)
3. Глобальные скиллы
4. Дефолты агента

При конфликте одноимённого проектного и глобального скилла побеждает **проектный**. Зафиксировать это явно в `AGENTS.md`.

## Протокол записи

- В память — только проверенный факт.
- Гипотезы — в `Knowledge/Proposals/`, не в правила.
- Сменился стек, команда или структура — обновить `AGENTS.md` в том же коммите.
- Правила не переписывать молча; историю решений не терять (Reports / Proposals).

## Протокол чтения

1. `AGENTS.md` — целиком.
2. `Knowledge/` и `Reports/` — только по `.ai/index.md`, нужные файлы.
3. `Memory/` — только для текущей длинной задачи (`NOW.md` / `STATE.md`).

## Адаптеры агентов

Только тонкая ссылка на `AGENTS.md`, без копий правил.

| Агент | Файл-вход |
|-------|-----------|
| Claude Code | `CLAUDE.md` → `@AGENTS.md` |
| Codex / ZCode | `AGENTS.md` (он же вход) |
| Cursor | `.cursor/rules` → ссылка на `AGENTS.md` |
| OpenCode | вход по документации агента → `AGENTS.md` |
| Pi | проектные skills + `AGENTS.md` |

## Чего не хранить

Секреты и токены; логи и дампы; историю задач как истину; чужой код; сгенерированное без ревью; полные копии `.ai/` во внешнем Vault.

## Настройка

1. Создать `AGENTS.md` (правила, карта кода/доков, проверки) в бюджете.
2. Создать `.ai/` с `glossary.md`, `index.md`; при необходимости `project-rules.md`, `Knowledge/`, `Reports/`, `Memory/`.
3. Положить проектные процедуры в `.agents/skills/`.
4. Поставить адаптеры-ссылки на `AGENTS.md`.
5. В `AGENTS.md` указать приоритет источников и победу проектного скилла над глобальным.

**Готово, когда:** ссылки живые; одна истина на факт (нет копий правил в адаптерах); размер в бюджете; адаптеры указывают на `AGENTS.md`.

## Миграция прежних AI Docs

1. Прочитать существующие `AGENTS.md`, `.ai/MEMORY.md`, `project-rules.md`, glossary — выделить уникальное.
2. Выбрать один источник истины. Внешний Vault не дублировать полной копией `.ai/`.
3. Роутинг MEMORY → в AGENTS/`index.md`; оперативное → `Memory/`; справки → `Knowledge/`; отчёты → `Reports/`.
4. Адаптеры (`CLAUDE.md` и др.) — короткие ссылки на `AGENTS.md`, без копий правил.
5. Сначала проверить ссылки; удаление старых файлов — только по согласованию. Исходники не удалять автоматически. Повтор настройки не перезаписывает пользовательские файлы.

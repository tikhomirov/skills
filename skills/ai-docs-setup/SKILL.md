# AI Docs Setup

## Ответственность
Этот скилл выбирает расположение документации и связывает входные инструкции со скиллами. Он не вводит второй, конкурирующий проектный фреймворк.

### Есть Obsidian Vault — основной режим
Использовать **obsidian-project-framework**: структура `Projects/<project>/`, AGENTS, задачи, append-only решения пользователя и `_agents/{Memory,Knowledge,Reports}`. Модули (включая возможный API) определяет и подтверждает пользователь; их документация read-only без явной просьбы о правке. При числе менее 10 допустимы 01_Имя/ в корне; Модули/ не создаётся автоматически.

```bash
obsidian-project-framework init --vault <путь> --project <id>
```

В репозитории остаются компактный `AGENTS.md`, `.project-id` и `.agents/skills/`. Процедурные скиллы не переносить в Knowledge; они устанавливаются `skills-install`.
За синтаксисом Markdown/Properties/Bases и инструментами приложения обращаться к **obsidian**. CLI `obsidian-project-framework` — помощь в соблюдении фреймворка, не замена его правил.

### Нет Vault — in-repo режим
Сохранить исходный принцип AI Docs: единый источник правил, короткая точка входа, выборочное чтение и отделение скиллов от знаний.

```text
AGENTS.md                  # Правила, краткая архитектура, карта кода и документации
.ai/
  project-rules.md          # Только дополнительные подробные правила при необходимости
  glossary.md               # Термины
  Memory/
    NOW.md
    STATE.md
    sessions/
  Knowledge/
  Reports/
.agents/skills/             # Процедуры для агентов, не проектные знания
```

Это запасное размещение документации, а не отдельный CLI-режим Obsidian Project. Если нужны задачи, решения, компоненты и их жизненный цикл — применять правила obsidian-project-framework к локальной базе вручную, не поддерживать два набора истины одновременно.

## Миграция прежнего AI Docs
1. Прочитать существующие AGENTS, `.ai/MEMORY.md`, `project-rules.md` и glossary; выделить уникальные сведения.
2. Выбрать один источник истины. Внешний Vault не дублировать полной копией `.ai/`.
3. Роутинг MEMORY перенести в AGENTS/индексы, оперативную память — в Memory, справки — в Knowledge, отчёты — в `_agents/Reports/`. Правила и архитектуру оставить доступными с входа.
4. `CLAUDE.md` и другие адаптеры — короткие ссылки на AGENTS, без копий правил.
5. Сначала проверить ссылки и согласовать удаление старых файлов; исходники не удалять автоматически. Повтор настройки не перезаписывает пользовательские файлы.

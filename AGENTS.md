# AGENTS.md — Agent Skills Collection

## Назначение
Репозиторий содержит скиллы и вспомогательные CLI для AI-агентов. Основной источник скиллов — `skills/`.

## Где искать
- `skills/obsidian/`: точные инструкции по инструментам и форматам Obsidian. Не проектный процесс.
- `skills/obsidian-project-framework/`: фреймворк работы над проектами на базе Obsidian — структура, задачи, решения, память, знания, отчёты.
- `skills/ai-docs-setup/`: настройка входных инструкций и миграция прежней `.ai/`, без второго конкурирующего фреймворка.
- `bin/skills-install`, `bin/obsidian-project-framework`: только настоящие исполняемые точки входа без расширений.
- `src/skills-install/`: установщик; `src/obsidian-project-framework/`: реализация вспомогательных команд фреймворка.
- `src/obsidian-project-framework/templates.mjs`: генерируемые правила, карточки и шаблоны; `paths.mjs`: канонические пути.
- `tests/`: тесты CLI, структуры, ссылок, безопасности и идемпотентности.

## Правила изменений
- Отвечать по-русски, кратко. Не менять реальные проекты и Vault без явного поручения.
- `obsidian-project-framework` упрощает соблюдение правил фреймворка, но не заменяет их. Без CLI агент выполняет тот же протокол вручную.
- Для изменений структуры синхронно обновлять скилл, рецепты, пути, шаблоны, команды, README и тесты.
- Повтор команды с теми же входными данными при том же состоянии — успешный no-op: без дублей, переименований, повторного журнала и изменения дат/mtime.
- `task create` идентифицируется `--key`, без него — точным названием. Для новой одноимённой задачи нужен другой ключ.
- `--dry-run` не пишет ничего, включая каталоги и lock-файлы. Неизменившийся контент не перезаписывать.
- Никаких HUMAN/AGENT/Agents-зон: рабочая папка `_agents/` с базовыми Memory, Knowledge, Reports. Дополнительные рабочие материалы допустимы.
- Состав, названия и расположение модулей подтверждает пользователь. API — возможный модуль, не обязательный раздел; init не создаёт модули.
- Документация модулей (Модули/ или 01_…/ в корне) read-only без явной просьбы пользователя о правке. Подтверждение списка модулей не является разрешением менять их документы.
- Решения/ — append-only события с источником подтверждения, датой и стабильными id задач. Исправления — новые события, оригиналы не переписывать. Живой таймлайн и текущие ссылки хранить в _agents/Knowledge/.
- _Задачи.base — обязательная нативная канбан-доска Obsidian 1.14+, не table/cards. init создаёт её по умолчанию для всех карточек из Tasks/ (или существующей Задачи/).
- Корневой _statuses.md — единственный источник статусов, их описаний, ролей и порядка колонок. Init создаёт начальные backlog/in-progress/done; пользователь может менять/расширять их, агент — только по его просьбе. Существующий реестр не перезаписывать.
- Перед созданием/сменой статуса читать _statuses.md, не использовать фиксированный список из скилла/констант. После изменения реестра или drag-and-drop выполнить task sync; неизвестные значения не преобразовывать и не скрывать молча.
- Скиллы и шаблоны универсальны: никаких ссылок на локальные проекты, персональные пути и частные правила.
- При смене статуса задачи обновлять имя, свойства, статусный тег, ссылки, индекс и память вместе.
- Код описывает фактическое поведение; принятые пользователем решения — требования. Не подменять одно другим.
- Скрипты не утверждают решения, не выдумывают успешные проверки и не копируют секреты в документацию.
- Не удалять исходники при миграции; не коммитить и не пушить без поручения.

## Проверки
```bash
make check
make test
make help
```
Тесты работают во временных каталогах, без изменения пользовательского Vault.

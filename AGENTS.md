# Agent Skills Collection

## Карта
- `skills/{System,code,engineering,seo,tools,ui-ux}/<skill>/SKILL.md` — тематические источники; один скилл — один каталог. Подключение агентов: `docs/skills-storage.md`.
- `skills/in-dev/` — экспериментальные скиллы в разработке. Не активировать, не использовать как инструкции или источник рекомендаций, не устанавливать и не подключать агентам по умолчанию. Работать с ними только по явному поручению пользователя; наличие `SKILL.md` не означает готовность.
- `bin/` — только исполняемые входы; `src/` — реализация; `tests/` — проверки.
- OF (Obsidian Framework) — экспериментальный проект и скилл `skills/in-dev/obsidian-framework/`, не готовое решение и не обязательный процесс репозитория. Его реализация, шаблоны и тесты: `src/obsidian-project-framework/`, `bin/obsidian-project-framework`, `tests/obsidian-project-framework/`; старые технические имена сохранены.

## Правила
- Отвечать кратко по-русски. Перед/после правок проверять обоснованность рекомендаций и фактический diff; диапазон не расширять без необходимости. Экспериментальные скиллы из `skills/in-dev/` для этих проверок не применять.
- При изменении контракта согласованно обновлять код, скиллы, шаблоны, README и тесты. Инструкции короткие, однозначные, без личных путей/проектов; подробности — в рецептах.
- Команды идемпотентны; неизменившиеся файлы не переписывать. Dry-run не создаёт даже каталоги/lock.
- Следующие правила OF относятся только к его разработке по явному поручению, не активируют экспериментальный скилл: _agents — рабочая зона, модули — read-only без явной просьбы, Решения — append-only.
- _statuses.md — короткий источник статусов; ручной status с доски приоритетнее имени/тегов. Task sync не отменяет решение человека; отметка Done не доказывает проверки.
- Активного индекса нет; канбан — _Задачи.base, архив — _archive с табличной БД и индексом. Не переиспользовать ID.
- Секреты не копировать. Живые проекты/Vault менять только по поручению, с резервной копией. Миграция не удаляет историю. Коммит/push — только по разрешению.

Проверки: `make check`, `make test`, `make help`. Тесты — во временных каталогах, не в пользовательских проектах.
